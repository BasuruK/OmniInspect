Gather in chat. Submit once.

Proposed update to add_database · no new process · no MCP setup form

01 · UserIDE chat“Add my development Oracle database and connect to it.”
02 · AgentGatherCollect name, host, port, service, username and password. Ask only for missing details; propose port 1521.
03 · AgentSubmitCall add_database once, with all fields and connect: true.
04 · OmniViewExecuteValidate → save connection → attempt Oracle login → run existing permission/package checks → select database on success → notify TUI.
05 · AgentReport“Connection saved and verified; DEV is selected.” Report saved and connected states separately if connection fails.

The boundary is explicit

The agent gathers information through ordinary IDE conversation. OmniView receives a complete tool request; it does not ask the IDE to render a form.

One tool call

add_database({
  id: "DEV",
  host: "oracle-dev.local",
  port: 1521,
  service: "DEV_PDB",
  username: "DEV_USER",
  password: "<REDACTED>",
  connect: true
})

Illustrative arguments. Actual password required; never echo it in results or logs. IDE chat/tool history may retain submitted credentials; use an IDE secret input when available.

Small contract change

CaseSavedResult
Save + connect succeedsYesconnected: true; return database ID and selected database.
Oracle connection failsYesconnected: false; structured error. Preserve previous database selection. Retry connect_database with the returned ID.
Fields missing / invalidNoReturn missing_fields / field errors. Agent gathers corrections, then submits complete arguments.
connect omitted / falseYesKeep existing save-only behavior. Existing connect_database remains available.

Implementation scope

Update tool schema, descriptions, validation and results. Reuse connection logic internally; keep one external call. One call is not an atomic save-and-connect transaction.

Restart fix stays separate

Stateless HTTP removes stale-session dependence. Removing bearer auth removes token configuration. This workflow change replaces elicitation.

“Connected” follows the current tool’s connection verification and database selection semantics; it does not create a new permanent Oracle session.
